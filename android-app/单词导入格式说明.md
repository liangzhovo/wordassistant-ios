# 单词助手（Android 版）单词导入 JSON 格式说明

本文件说明如何构造一个可被 Android 版单词助手（`android-app`）的 **📥 导入单词本（恢复）** 功能识别的 JSON 文件。

导入入口：应用内 **我的** 页 → `📥 导入单词本（恢复）` → 选择列表（全部 / 指定列表）→ 选择 JSON 文件。
后端处理逻辑位于 `app/src/main/python/app.py` 的 `@app.route('/api/import', methods=['POST'])`。

---

## 1. 顶层结构

```json
{
  "app": "WordAssistant",          // 可选：应用标识（元信息，导入端忽略）
  "version": 1,                    // 可选：格式版本（元信息，导入端忽略）
  "exported_at": "2026-08-30 10:00:00",  // 可选：导出时间（元信息，导入端忽略）
  "exported_list_id": null,        // 可选：导出来源列表（元信息，导入端忽略）
  "word_lists": [ ... ],           // 可选：列表定义（仅未指定目标列表时导入）
  "user_words": [ ... ],           // 必填：单词数组
  "settings": { ... }              // 可选：应用设置（导入后会覆盖同名设置）
}
```

> **唯一硬性要求**：顶层必须包含 `user_words` 数组，否则后端返回 `数据格式错误`（HTTP 400）。

---

## 2. word_lists（列表定义，可选）

每个列表对象：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 列表 ID（可选，缺省时数据库自增） |
| name | string | 列表名称（必填，缺省为"导入列表"） |
| created_at | string | 创建时间（可选） |

导入规则：`INSERT OR IGNORE` —— 已存在的 ID 会被跳过，不会覆盖已有列表。

---

## 3. user_words（单词数组，必填）

每个单词对象可含以下字段，**多余字段会被忽略**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| word | string | ✅ | — | 单词本身，导入时**不会**强制转小写，建议统一小写 |
| list_id | int | 否 | 1 | 所属列表 ID（对应 word_lists 中的 id） |
| added_date | string | 否 | 当前时间 | 加入日期，格式 `YYYY-MM-DD HH:MM:SS` |
| review_count | int | 否 | 0 | 累计复习次数 |
| forget_count | int | 否 | 0 | 累计忘记次数 |
| next_review | string | 否 | null | 下次复习时间；**留空/null 表示立即进入复习队列** |
| mastered | int | 否 | 0 | 0=未掌握（参与复习），1=已掌握（不参与复习） |
| phonetic | string | 否 | null | 音标，如 `/həˈləʊ/` |
| translation | string | 否 | null | 中文释义，如 `int. 你好；喂` |
| easiness_factor | number | 否 | 2.5 | SM-2 记忆难度系数（0~3 之间，越大越容易） |
| interval | int | 否 | 0 | SM-2 间隔天数 |

**行为细节**：

- **自动补全**：`phonetic` / `translation` 留空时，下次打开单词本（`GET /api/wordbook`）会自动从内置词库 `mdx` 表查词并回填。
  因此**最简导入可以只写 `word` + `list_id`**，音标和释义交给系统补全。
- **去重**：按 `(word, list_id)` 复合主键 `INSERT OR IGNORE` 去重，重复导入同一单词不会报错，只会跳过。
- **SM-2 字段**：`easiness_factor`、`interval` 为间隔重复算法字段，手工造数据时保持默认值（2.5 / 0）即可；`review_count` 已大于 0 时建议同时给出合理的 `interval` 与 `next_review`，否则复习安排可能异常（可留空让系统按新词处理）。

---

## 4. settings（应用设置，可选）

形如 `{ "key": "value" }` 的键值对象，导入使用 `INSERT OR REPLACE`，**会覆盖应用内同名设置**。
常见键：`theme`（system/light/dark）、`dailyLimit`（每日新词数）、`review_mode`、`weights`、`autoLimit`、`autoAdapt`、`reminder_enabled`、`reminder_time` 等。
不需要覆盖设置时，直接省略该字段即可。

---

## 5. 最简可用示例

只导入一批单词到默认列表（音标/释义自动补全）：

```json
{
  "user_words": [
    { "word": "apple" },
    { "word": "banana", "list_id": 1 },
    { "word": "cherry", "list_id": 1, "translation": "n. 樱桃" }
  ]
}
```

---

## 6. 导入到指定列表（target_list_id）

导入界面上选择某个具体列表时，前端会自动在 JSON 顶层追加 `target_list_id`，后端会把**所有单词统一导入该列表**，并跳过 `word_lists` 的创建。手写 JSON 时无需关心此字段，但也可主动携带：

```json
{
  "target_list_id": 3,
  "user_words": [ { "word": "apple" } ]
}
```

## 7. 兼容性说明

- 本仓库根目录的 `8上.json`、`9上.json`（外研版课本词表备份）即为符合该格式的现成导入文件，可直接通过导入功能恢复。
- 桌面版（仓库根目录 `app.py`）目前**尚未**实现 `/api/import` 与 `/api/export` 端点；如需桌面版也支持导入，可把 Android 版 `app.py` 中 `export_data` / `import_data` 两段逻辑移植过去。
- 示例文件见同目录 `单词导入示例.json`。
